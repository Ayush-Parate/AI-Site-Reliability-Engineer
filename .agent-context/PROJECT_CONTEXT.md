# Project Context

## Overview
AI Site Reliability Engineer (AI-SRE): an AI agent that watches a running
microservices demo app, detects incidents with plain-code rules, finds the root
cause with cited evidence, applies safe fixes automatically, gates risky ones
behind human approval, and writes a postmortem. Built for hackathon problem
statement AIA-02. No Docker required; services run as plain local processes.

## Technology stack
- Python 3.13 (Homebrew `python@3.13` in `.venv`).
- FastAPI + Uvicorn (services and dashboard), httpx (HTTP client / metrics),
  prometheus-client (metrics), PyYAML (config), python-dotenv (env), openai SDK
  (connecting locally to Ollama running qwen2.5). Tests with pytest.
- SQLite for inventory (`data/inventory.db`) and observability/metrics/incidents (Phases 3+).

## Architecture
```
gateway :8000 --> orders :8001 --> payments :8002
                        \--> inventory :8003 --> sqlite
Supervisor + Chaos CLI --> logs/*.log + /metrics --> Observability (SQLite)
  --> Detector (rules) --> Incident (T0) --> Agent loop (LLM + tools, tiered)
  --> Fix pipeline (tier > limit > snapshot > apply > verify) --> Timeline/Postmortem/Dashboard
```

## Key folders
- `services/{gateway,orders,payments,inventory}/` — demo microservices (Phase 1, implemented).
- `services/common/` — shared logging, Prometheus metrics, chaos, and middleware (Phase 1, implemented).
- `load.py` — steady load generator (Phase 1, implemented).
- `sre/` — supervisor, chaos, observability, detector, agent, tools, fixer,
  postmortem, llm, and `dashboard/`.
- `sre/supervisor.py` — process tracking, lifecycle, and change logging (Phase 2, implemented).
- `sre/chaos.py` — 8 failure injectors and random chaos CLI (Phase 2, implemented).
- `sre/llm.py` — provider wrapper with failover (Phase 0, implemented).
- `config/` — `dependencies.yaml` (call graph), `slo.yaml` (thresholds).
- `logs/`, `data/`, `reports/` — runtime output (gitignored).
- `tests/` — pytest suite (LLM, services, supervisor, chaos).
- `run.py` — single entry point.

## Setup and commands
- Create venv: `/opt/homebrew/bin/python3.13 -m venv .venv`
- Install: `.venv/bin/python -m pip install -r requirements.txt`
- Run all services + traffic: `.venv/bin/python run.py`
- Run only services: `.venv/bin/python run.py --services`
- Supervisor CLI: `.venv/bin/python sre/supervisor.py status|start-all|stop-all|restart <svc>`
- Chaos CLI: `.venv/bin/python sre/chaos.py crash|latency|error-burst|memory-leak|cpu-hog|bad-deploy|dependency-down|db-lock|clear|random`
- Test LLM providers: `.venv/bin/python run.py --test-llm`
- Tests: `.venv/bin/python -m pytest -v`

## Current state
Phase 7 (Timeline, Postmortem and Metrics) is complete:
- Metric Collector and Log Reader populate SQLite (`data/observability.db`).
- Rule-based detector (`sre/detector.py`) watches for SLO breaches against `config/slo.yaml`.
- Accurate T0 anomaly timestamp recording and time-to-detect (TTD) computation.
- Agent (`sre/agent.py`) + allowlisted tools (`sre/tools.py`) investigate incidents with
  LLM tool-calling, provider failover, 12-step cap, and structured JSON diagnosis.
- T1 (diagnosis time) and time-to-diagnosis (`T1 - T0`) recorded on incident metadata.
- Fixer (`sre/fixer.py`) enforces action tiers, persisted approvals, circuit breaking,
  snapshots, apply/verify, incident resolution, and escalation.
- Postmortem, Modular Reports & Timeline (`sre/postmortem.py`, `sre/reports/`):
  - Audit-backed incident timeline with linked evidence IDs (`LOG-x`, `MET-x`, `CHG-x`).
  - Strict validator rejecting any postmortem claim without evidence citations.
  - Modular, 8-category structured storage per incident (`reports/<INC-ID>/` with `metadata.json`, `<section>.json`, `postmortem.md`) and backward-compatible `reports/INC-<id>.md`.
  - Lazy loading REST APIs: `/api/reports`, `/api/reports/{id}`, `/api/reports/{id}/sections`, `/api/reports/{id}/sections/{section_id}`.
  - Metrics computation (TTD, TTDiag, TTR) and benchmark comparison table vs human manual baseline (18.3x average speedup across 8 failure modes).
- 112 passing tests across 12 test modules in `pytest`.
- Live multi-process verification confirmed through `tests/verify_phase7.py`.

## Constraints
- Code decides, LLM reasons. Detection/tiers/verification are plain code.
- Evidence IDs generated by code; postmortem rejects uncited claims.
- Allowlist tools with argument validation; tier checks live in code.
- Secrets only in `.env` (gitignored); never commit keys or real `.env`.
- Generalize, do not hardcode per-scenario scripts.
